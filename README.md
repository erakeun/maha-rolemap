# MACH 업무분장 스튜디오

부서별 조직도와 업무분장을 함께 편집하는 독립 웹 모듈입니다. 가상 구성원 10명과 A–Z 업무 26개를 예제로 제공합니다.

## 기능

- 부서별 최대 50명, 최대 30개 부서, 부서별 최대 500개 업무
- 이름 일괄 입력 → 직책·보고 관계 자동 생성, 이후 자유 수정
- 조직도에서 사람 손잡이를 끌어 보고 대상 변경; 순환 구조 차단
- 업무 끌어놓기: 담당 이동 또는 기존 담당자를 유지한 공동 담당 추가
- 업무별 선택적인 주담당 1명, 협업 담당 여러 명 또는 주담당 미지정 공동 담당, 범위 메모, 분류, 중요도, 난이도
- 조직도, 구성원별 업무분장표, 업무 보드, 검색, 미배정·공동 담당 필터
- 조직도 ‘업무내용 표시’ 스위치: 모든 업무명·주담당/협업·메모 표시 또는 숨김. 기본 켜짐이며 브라우저별 설정을 기억합니다. 업무는 카드에서 직접 편집하거나 끌어 이동할 수 있습니다.
- 난이도 점수를 공동 담당 인원으로 나눠 업무량을 표시 (실제 소요 시간·성과 점수 아님)
- 사람의 ID를 유지하는 후임자 교체와 인수인계 기록
- 사람 삭제 시 업무 보존, 공동 담당 승계, 하위 구성원의 보고 대상 재연결
- 현재 창의 최근 40단계 실행 취소 / 다시 실행 (Ctrl 또는 Cmd + Shift + Z)
- 최근 100건 변경 기록, 브라우저 자동 저장, 전체 워크스페이스 JSON 내보내기·불러오기
- JSON 유효성 검사, 가져오기 전 요약·교체 확인, 직후 실행 취소
- A4/A3 · 가로/세로 · 조직도/업무분장표 · 한 장 맞춤/여러 장 · 상세 메모 포함 선택
- 모바일에서 드래그 대신 업무 편집창으로 담당자 지정

## 실제 부서 자료에서 반영한 기능

- 팀과 업무 파트를 계층으로 관리하며 개인의 직책·직급·고용구분을 분리합니다. 직급만으로 보고 관계를 결정하지 않습니다.
- 팀·파트별 보기에서는 카드 크기를 축소하지 않고 읽기 좋은 크기로 표시합니다. 특정 파트만 필터링하거나 업무 보관함을 열 수 있습니다.
- 별도 센터는 대표 표기, 별도 인원, 업무 범위를 관리합니다. 이름이 없는 인원은 구성원으로 임의 생성하지 않으며 본부 구성원 수에 합산하지 않습니다.
- 원본 자료의 기준 월, 인원 차이, 역할이 불명확한 부분을 `reference` 검토사항으로 보존합니다.
- 팀·파트별 업무분장표와 인쇄 전 미리보기를 제공합니다. 전체 자료와 검토사항을 포함하므로 한 장에 맞추면 작아질 수 있습니다.
- 실제 조직의 실명·업무 자료는 저장소에 포함하지 않습니다. 사용자가 직접 불러온 JSON은 해당 브라우저에 저장됩니다.

## 실행

빌드와 별도 의존성 설치가 필요하지 않습니다. 저장소 루트 디렉터리를 정적 웹 서버에서 제공하세요.

```sh
python3 -m http.server 4318 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:4318`을 엽니다. ES 모듈을 사용하므로 파일을 직접 더블클릭하는 방식 대신 HTTP 서버를 사용해야 합니다.

```sh
npm test
```

## MACH 통합

- 공개 PROJECT MACH: https://erakeun.github.io/ERICAAI/#project-28
- 공개 실행 도구: https://erakeun.github.io/ERICAAI/rolemap/
- 개인 작업 주소: https://maha-rolemap.hyungkeun.chatgpt.site/
- 개인마하: https://personal-mach.hyungkeun.chatgpt.site/#project=maha-rolemap&tab=links

공개 MACH에는 루트의 실행 파일 네 개만 복사해 배포합니다. 테스트·문서는 이 저장소에서 관리하며, 실제 부서 자료는 어느 배포본에도 포함하지 않습니다.

독립 정적 웹 모듈이며, 기존 포털에서는 도구 링크로 연결할 수 있습니다. 서버 로그인과 공동 저장은 포함하지 않습니다.

1. 루트의 `index.html`, `style.css`, `app.js`, `model.js` 파일 4개를 기존 MACH 웹 서버의 `/rolemap/` 같은 하위 경로로 배치할 수 있습니다. 리소스 참조는 상대 경로입니다.
2. 기존 메뉴에서 해당 경로로 연결하거나, 같은 서비스 내 별도 화면으로 구성할 수 있습니다.
3. `model.js`의 ID 기반 데이터 구조와 유효성 검증은 UI로부터 분리되어 있습니다.
4. 조직 공용 서비스로 확장할 때 `app.js`의 데이터 초기화·`save()`·`exportJSON()` 경계에 기존 MACH API를 연결합니다. 저장 성공 응답을 확인한 뒤 성공을 표시해야 합니다.
5. 서버는 부서별 조회/편집 권한, 데이터 검증, 동시 편집 버전 검사(예: revision 또는 ETag), 변경 이력을 제공해야 합니다. 현재 클라이언트 검증은 서버 권한 검사를 대신하지 않습니다.
6. 인원 교체는 현 구조에서 동일한 업무 자리의 `member.id`를 유지하고 이름을 변경합니다. 조직 전체의 직원 ID를 별도로 관리하는 서비스라면 `positionId`와 `employeeId`를 분리해 연결하는 것이 적합합니다.

## 저장 범위

현재는 서버 데이터베이스와 공동 편집 기능 없이 **현재 브라우저의 localStorage**에 저장합니다. 다른 기기나 브라우저로 이동할 때 JSON을 사용하세요. 브라우저 저장소 삭제·시크릿 모드 종료 시 데이터가 사라질 수 있으므로 JSON 백업이 필요합니다.

JSON은 `schemaVersion: 1`이며 `departments`에 부서, `members`에 구성원, `tasks`에 업무, `units`에 팀·파트·별도 조직을 저장합니다. `primaryOwnerId`가 주담당을 가리킵니다. 명시적인 `null`이면 주담당 미지정이며 담당자들은 동등한 공동 담당입니다. 이 필드가 없는 기존 JSON은 `owners[0]`을 주담당으로 해석해 호환성을 유지합니다. 빈 `owners`는 미배정입니다. 모든 연결은 이름이 아닌 ID를 기준으로 합니다.

JSON 가져오기는 기본적으로 새 부서로 추가하며 기존 부서는 유지합니다. 같은 이름이 있으면 이름에 (가져옴)을 붙이고 새 부서 ID를 부여합니다. 사용자가 선택하면 전체 워크스페이스를 교체할 수도 있습니다. 구성원 단위 자동 병합은 지원하지 않습니다. 가져오기 전 백업 버튼과 가져오기 후 실행 취소를 제공합니다. 가져오기 직전 상태는 가능할 경우 `maha-rolemap:recovery` 키에도 저장하지만, 별도의 복구 UI는 없습니다.

## 검증 및 제한

- 핵심 데이터 동작 23개 자동 검사: 0~50명 조직도 생성, 업무 이동·공동 배정, 순환 방지, 삭제 시 업무 보존, 인수인계, 업무량 계산, JSON 왕복과 잘못된 파일 거부, 20명·500개 업무 데이터, 주담당 미지정 업무, 팀·파트 삭제, 기존 부서를 유지하는 가져오기, 별도 센터 집계.
- JavaScript 구문 검사 통과.
- 업무내용 표시 스위치 켜기·끄기, 새로고침 후 표시 설정 유지, 펼친 업무 직접 편집, 같은 조직 단계의 카드 높이 정렬 및 업무명 잘림 여부를 브라우저에서 확인했습니다.
- 실제 자료 28명·39개 업무를 새 부서로 추가하고 기존 예시 부서가 유지되는 것을 확인했습니다. 파트 필터, 주담당 미지정 공동 업무의 편집·재저장, 28명과 별도 센터가 포함된 인쇄 미리보기도 브라우저에서 확인했습니다.
- 실제 프린터 출력과 시스템 PDF 저장 결과는 검증하지 않았습니다.
- 한 장 인쇄는 모든 내용을 담기 위해 축소하므로, 구성원·업무·메모가 많으면 글씨가 작아질 수 있습니다. A3 또는 여러 장 모드를 선택할 수 있습니다.
- 웹 폰트는 Google Fonts에서 불러오며 연결이 없으면 시스템 글꼴을 사용합니다. 내부망에서는 `style.css` 첫 줄을 제거하고 조직의 글꼴을 지정할 수 있습니다.
- 다른 주소에서 쓰던 자료는 자동으로 이동하지 않습니다. 기존 사이트에서 JSON을 저장한 뒤 새 주소에서 불러오세요.
